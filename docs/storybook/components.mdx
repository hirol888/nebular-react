# Componentes e props

As páginas de cada componente são geradas por **Autodocs** a partir das interfaces
TypeScript. A tabela de props fica na seção **Controls** de cada página.

`ConflictResolutionDialog`, `SchemaForm`, `RecurrenceEditor`, `Combobox`,
`TableOfContents` e `ChatSources` mostram exemplos de composição independentes da aplicação.
As páginas de `CronInput` e `WorkflowDesigner` também incluem os novos modos opcionais.

As páginas de `RepeatableFieldset`, `FilePreview`, `VersionHistory`, `ImageComparison`,
`DockLayout`, `MediaPlayer` e `LocationPicker` apresentam exemplos prontos para experimentar.

e `DataMappingEditor`. As páginas de `TimeSlotPicker`, `TranscriptViewer` e `ImageAnnotator`

## Convenções comuns

Todos os componentes que aceitam estilos estendem `DefaultProps`:

```ts
interface DefaultProps<StylesNames, StylesParams> {
  className?: string;
  style?: React.CSSProperties;
  classNames?: Partial<Record<StylesNames, string>>;
  styles?: Partial<Record<StylesNames, CSSObject>>;
  unstyled?: boolean;
}
```

- `classNames` e `styles` sobrescrevem partes internas sem CSS global.
- `unstyled` remove os estilos padrão e mantém a estrutura/comportamento.
- Componentes polimórficos aceitam `component`:

```tsx
<Button component="a" href="https://example.com">
  Link
</Button>
```

## Tamanho, status, forma e aparência

```tsx
<Button size="medium" status="primary" shape="rectangle" appearance="filled" />
```

Opções comuns:

- `size`: `tiny` | `small` | `medium` | `large` | `giant`
- `status`: `basic` | `primary` | `success` | `info` | `warning` | `danger` | `control`
- `shape`: `rectangle` | `semiround` | `round`
- `appearance`: `filled` | `outline` | `ghost` | `hero`

## Controlado e não controlado

| Componente           | Valor                     | Padrão                  | Callback            |
| -------------------- | ------------------------- | ----------------------- | ------------------- |
| Select               | `selected`                | `defaultSelected`       | `onSelect`          |
| Autocomplete         | `value`                   | `defaultValue`          | `onChange`          |
| DataGrid (página)    | `page`                    | `defaultPage`           | `onPageChange`      |
| DataGrid (ordenação) | `sortKey`/`sortDirection` | `defaultSortKey`        | `onSortChange`      |
| DataGrid (seleção)   | `selectedRowIds`          | `defaultSelectedRowIds` | `onSelectionChange` |
| Pagination           | `page`                    | `defaultPage`           | `onChange`          |
| Accordion            | `activeItems`             | `defaultActiveItems`    | `onChange`          |
| Tabset               | `activeTabIndex`          | —                       | `onTabChange`       |
| Tags                 | `value`                   | `defaultValue`          | `onChange`          |

## Localização e i18n

```tsx
<NebularProvider locale="pt-BR" messages={{ 'dataGrid.undo': 'Voltar' }}>
  <App />
</NebularProvider>
```

- `locale` BCP 47 (`en-US` padrão) seleciona o catálogo embutido (`en-US`/`pt-BR`).
- `messages` sobrescreve chaves do catálogo; `useNebularLocale()` expõe `t(key, fallback, params)`.
- Datas, horas e números usam o locale do provider quando o componente não recebe `locale`.
- Componentes com muitas strings aceitam `labels` tipados, com precedência sobre o catálogo.
- `dir="rtl"` continua disponível no provider.

## Select e Autocomplete

```tsx
<Select
  options={options}
  searchable
  clearable
  loading={isLoading}
  nothingFoundMessage="Nenhum resultado"
  onSearchChange={(query) => fetchOptions(query)}
  onSelect={setSelected}
/>
```

- `searchable` habilita o campo de busca no dropdown.
- Com `onSearchChange`, a busca é assíncrona e o componente não filtra localmente.
- Sem `onSearchChange`, o filtro local usa `filterOption`.
- `virtualized`/`virtualizedMaxHeight` habilitam virtualização, inclusive em grupos.
- O teclado navega apenas pelas opções visíveis.

## DataGrid

```tsx
<DataGrid
  data={users}
  columns={[
    { key: 'name', title: 'Nome', sortable: true },
    { key: 'email', title: 'E-mail' },
    { key: 'status', title: 'Status', render: (user) => <Badge text={user.status} /> }
  ]}
  pageSize={10}
  withSelection
  onSelectionChange={setSelectedIds}
  caption="Usuários"
/>
```

Recursos: ordenação, filtros por coluna, paginação, seleção controlada/não controlada,
seleção da página com estado indeterminado, `emptyState`, `caption`, `ariaLabel`,
virtualização de linhas e resize/reorder de colunas.

## Filtros por coluna

```tsx
<DataGrid
  data={users}
  columns={[
    { key: 'name', title: 'Nome', sortable: true, filterable: true },
    { key: 'email', title: 'E-mail', filterable: true },
    { key: 'status', title: 'Status', filterValue: (user) => user.status }
  ]}
  withColumnFilters
  onFilterChange={setFilters}
/>
```

- `column.filterable` habilita a busca da coluna.
- `column.filterValue` permite filtrar por um valor derivado.
- `filterValues`/`defaultFilterValues` controlam os filtros; `onFilterChange` recebe
  `Record<string, string>`.
- O filtro é case-insensitive, por substring, e volta para a página 1.

## Virtualização de linhas

```tsx
<DataGrid
  data={manyRows}
  columns={columns}
  pageSize={500}
  withPagination={false}
  virtualized
  virtualizedRowHeight={44}
  virtualizedMaxHeight={420}
  overscan={3}
/>
```

Apenas a janela visível da página atual é renderizada, com header sticky.

## Redimensionamento de colunas

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withColumnResize
  columnWidths={{ name: 220, email: 260 }}
  onColumnWidthChange={setWidths}
  minColumnWidth={80}
/>
```

Arraste o handle ou use `ArrowLeft`/`ArrowRight` com o handle focado (`Shift` move
25px). `column.minWidth`/`column.maxWidth` refinam o limite por coluna.

## Reordenação de colunas

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withColumnReorder
  columnOrder={order}
  onColumnOrderChange={setOrder}
/>
```

Arraste o handle ou use `Alt+ArrowLeft`/`Alt+ArrowRight`. A ordem é baseada em
`column.key`; colunas novas são anexadas ao final.

## Visibilidade de colunas

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withColumnVisibility
  hiddenColumnKeys={hidden}
  onHiddenColumnsChange={setHidden}
/>
```

`column.hideable={false}` impede ocultar uma coluna. A última coluna visível não pode ser
ocultada.

## Expansão de linhas

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withRowExpansion
  renderRowExpansion={(row) => <UserDetails user={row} />}
/>
```

`expandedRowIds`/`defaultExpandedRowIds` controlam o estado. A expansão desativa a
virtualização porque as linhas passam a ter altura variável.

## Exportação CSV

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withExport
  exportFileName="users.csv"
  exportScope="filtered"
  onExport={(csv, fileName) => upload(csv, fileName)}
/>
```

`exportScope` aceita `filtered` ou `page`. `column.exportValue`/`exportTitle`/`exportable`
customizam o CSV. Sem `onExport`, o componente baixa o arquivo via Blob. O helper
`createDataGridCsv` também é exportado.

## Agrupamento

```tsx
<DataGrid
  data={rows}
  columns={columns}
  groupBy="role"
  groupLabel={(key, rows) => `${key} (${rows.length})`}
  collapsibleGroups
  expandedGroupKeys={expandedGroups}
  onExpandedGroupsChange={setExpandedGroups}
/>
```

`groupBy` aceita chave, array de chaves (agrupamento aninhado) ou função. `renderGroupHeader`
customiza o cabeçalho. Agrupamento desativa a virtualização porque as linhas de grupo quebram
a altura fixa.

## Edição de linhas

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withRowEditing
  onRowEdit={(row, changes) => updateRow(row.id, changes)}
/>
```

`column.editable={false}` remove a coluna do editor. `renderRowEditor(row, onSave,
onCancel)` substitui o editor padrão. `onRowEdit` recebe somente os campos alterados.

## Server-side

```tsx
<DataGrid
  data={currentPageRows}
  columns={columns}
  serverSide
  totalRows={total}
  page={page}
  pageSize={20}
  onPageChange={setPage}
  sortKey={sortKey}
  sortDirection={sortDirection}
  onSortChange={setSort}
  filterValues={filters}
  onFilterChange={setFilters}
  loading={loading}
/>
```

`serverSide` desativa paginação, ordenação e filtro locais; `data` contém apenas a página
atual e `totalRows` define o total de páginas. Use estado controlado para refletir o
servidor. `loading` exibe o overlay de carregamento.

## Column pinning

```tsx
<DataGrid
  data={rows}
  columns={[
    { key: 'name', title: 'Nome', pinned: 'left', width: 200 },
    { key: 'email', title: 'E-mail', width: 240 },
    { key: 'status', title: 'Status', pinned: 'right', width: 140 }
  ]}
/>
```

`column.pinned` fixa à esquerda/direita; `pinnedColumns`/`defaultPinnedColumns`/
`onPinnedColumnsChange` permitem controlar por `key`.
Definir `width` explícito é recomendado. Pinning é ignorado quando há headers multi-nível.

## Headers multi-nível

```tsx
<DataGrid
  data={rows}
  columns={[
    { key: 'name', title: 'Nome', sortable: true },
    {
      key: 'contact',
      title: 'Contato',
      children: [
        { key: 'email', title: 'E-mail', sortable: true, filterable: true },
        { key: 'phone', title: 'Telefone' }
      ]
    }
  ]}
  withColumnFilters
/>
```

`children` cria grupos com `colSpan` automático; folhas mantêm sort/filter/resize/export.
Virtualização é desativada com headers multi-nível.

## Resumo e agregações

```tsx
<DataGrid
  data={rows}
  columns={[
    { key: 'name', title: 'Nome' },
    { key: 'total', title: 'Total', aggregate: 'sum', summaryValue: (row) => row.total },
    { key: 'ativos', title: 'Ativos', aggregate: (rows) => rows.filter((row) => row.active).length }
  ]}
  withSummary
  summaryScope="filtered"
  summaryLabel="Total"
/>
```

`aggregate` aceita `sum`, `avg`, `min`, `max`, `count` ou função de `rows`.
`summaryScope` alterna entre dados filtrados e página atual; `summaryFormatter` formata o valor.
`withGroupSummary` adiciona subtotais por grupo.

## Operadores de filtro

```tsx
<DataGrid
  data={rows}
  columns={[
    { key: 'name', title: 'Nome', filterable: true, filterOperator: 'startsWith' },
    { key: 'total', title: 'Total', filterable: true, filterOperator: 'gte' }
  ]}
  withColumnFilters
/>
```

`contains` (default), `notContains`, `equals`, `notEquals`, `startsWith`, `endsWith`,
`gt`, `gte`, `lt`, `lte`, `isEmpty` e `isNotEmpty`.

## Reordenação de linhas

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withRowReorder
  onRowReorder={(fromIndex, toIndex) => move(fromIndex, toIndex)}
/>
```

Handle de arraste + `Alt+ArrowUp`/`Alt+ArrowDown`; índices relativos à página atual.

## Menu de coluna

```tsx
<DataGrid data={rows} columns={columns} withColumnMenu withColumnVisibility />
```

Ordenar, fixar à esquerda/direita, desafixar e ocultar; fecha com `Escape` ou clique fora.

## Edição por célula

```tsx
<DataGrid
  data={rows}
  columns={columns}
  withCellEditing
  onCellEdit={(row, columnKey, value) => update(row.id, columnKey, value)}
/>
```

Clique/Enter inicia, Enter/blur confirma, `Escape` cancela. `editingCell`/`defaultEditingCell`/
`onEditingCellChange` controlam a célula ativa e `renderCellEditor` substitui o input.

## Virtualização de colunas

```tsx
<DataGrid data={rows} columns={columns} virtualizeColumns />
```

Renderiza apenas as colunas visíveis no scroll horizontal, com spacers e `<colgroup>`.
Desativada com headers multi-nível, `groupBy` ou colunas fixas; helper
`getVirtualColumnRange` exportado.

## Saved views

```tsx
<DataGrid data={rows} columns={columns} withViews viewStorageKey="users-grid" />
```

`views`/`defaultViews`/`onViewsChange`, `activeViewId`/`onActiveViewChange`; salva sort, filtros,
colunas, ordem, larguras, pinning e pageSize. `viewStorageKey` persiste no localStorage.

## Filtros por range

```tsx
<DataGrid
  data={rows}
  columns={[
    {
      key: 'total',
      title: 'Total',
      filterable: true,
      filterType: 'number',
      filterOperator: 'between'
    }
  ]}
  withColumnFilters
/>
```

`filterType` `text`/`number`/`date`, operadores `between`/`notBetween` e limites abertos.

## Seleção de intervalo e clipboard

```tsx
<DataGrid data={rows} columns={columns} withRangeSelection />
```

Clique + `Shift+clique` seleciona; `Ctrl/Cmd+C` copia o intervalo como TSV.
`rangeSelection`/`onRangeSelectionChange` controlam a seleção.

## Undo/redo, Excel e server-side

```tsx
<DataGrid data={rows} columns={columns} withUndoRedo withExcelExport excelFileName="clientes" />
<DataGrid data={pageRows} columns={columns} serverSideSorting serverSideFiltering loading={loading} />
```

- `withUndoRedo`: histórico de edições/reordenação com `Ctrl/Cmd+Z`, `Ctrl/Cmd+Shift+Z`,
  `Ctrl+Y` e botões acessíveis; `maxHistory` limita o histórico.
- `withExcelExport`: HTML Office (`.xls`) com colunas visíveis/agregações e escape de fórmulas.
- `serverSideSorting`/`serverSideFiltering`: não transformam localmente, apenas emitem
  `onSortChange`/`onFilterChange`; `aria-busy` durante `loading`.
- `getRowHeight` habilita virtualização com alturas variáveis (incompatível com spans/expansão).

<DatetimePicker timeZone="America/New_York" date={instant} onDateChange={setInstant} />

## Componentes utilitários

### Chip e ChipGroup

```tsx
<Chip defaultChecked onChange={(checked) => save(checked)}>
  React
</Chip>

<ChipGroup
  label="Tecnologias"
  description="Selecione todas as que usa"
  data={['React', { value: 'vue', label: 'Vue' }]}
  multiple
  value={selected}
  onChange={setSelected}
  error={errors.technologies}
/>
```

- `Chip` usa `role="checkbox"`, `aria-checked` e variantes `filled`/`outline`/`light`.
- `ChipGroup` aceita `data` com strings ou `{ value, label, disabled }`; `multiple` alterna entre
  seleção única e múltipla. `label`/`description`/`error`/`required`/`orientation` são suportados.
- Em seleção múltipla o `onChange` recebe `string[]`; na única, `string` (ou `''` ao desmarcar).

### Fieldset e NativeSelect

```tsx
<Fieldset legend="Conta" description="Dados básicos" disabled={readonly}>
  <NativeSelect
    label="País"
    data={['BR', { value: 'US', label: 'Estados Unidos' }]}
    value={country}
    onChange={setCountry}
    required
  />
</Fieldset>
```

- `Fieldset` agrupa controles com `legend`, `description`, `variant="filled"` e `withBorder`.
- `NativeSelect` embrulha o `<select>` nativo e normaliza o callback para
  `onChange(value, event)`. Suporta `placeholder`, `error`, `description`, `size` e `required`.
- O asterisco de obrigatório é decorativo (`aria-hidden`); o nome acessível vem do `<label>`.

### SwitchGroup e RadioGroup

```tsx
<SwitchGroup
  label="Notificações"
  data={['email', 'push', 'sms']}
  value={channels}
  onChange={setChannels}
/>

<RadioGroup
  label="Plano"
  data={[
    { value: 'basic', label: 'Básico' },
    { value: 'pro', label: 'Pro' }
  ]}
  value={plan}
  onChange={setPlan}
  orientation="horizontal"
  name="plan"
/>
```

- `SwitchGroup` trabalha com arrays (`value`/`defaultValue`/`onChange`) e renderiza `Toggle` com
  `role="switch"`.
- `RadioGroup` continua aceitando filhos (`Radio`) e agora também `data`, `label`, `description`,
  `error`, `required`, `orientation` e `name`.
- Ambos usam `role="group"`/`role="radiogroup"` com nome acessível derivado de `label` ou
  `ariaLabel`.

### FileButton

```tsx
<FileButton
  onChange={(files) => setFiles(files)}
  multiple
  accept="image/*"
  reset
>
  <Button>Enviar imagens</Button>
</FileButton>
```

O input de arquivo fica oculto e é aberto pelo clique no elemento filho. `onChange` recebe
`File[] | null`; `reset` limpa o input após cada seleção para permitir reenviar o mesmo arquivo.

### ThemeIcon, ColorSwatch e Overlay

```tsx
<ThemeIcon status="success" variant="light" ariaLabel="Concluído">
  <Icon icon="checkmark" />
</ThemeIcon>

<ColorSwatch color="#3366ff" checked ariaLabel="Azul" onClick={selectColor} />

<Overlay fixed={false} opacity={0.6} blur={2} ariaLabel="Carregando" />
```

- `ThemeIcon`: `size`, `radius`, `variant` (`filled`/`light`/`outline`), `status`/`color`.
  Sem `ariaLabel` o ícone é decorativo (`aria-hidden`).
- `ColorSwatch`: `size`, `radius`, `withBorder`, `checked`; cores `transparent`/`none` usam o fundo
  quadriculado. A cor é o nome acessível padrão, sobrescrito por `ariaLabel`.
- `Overlay`: `opacity`, `color`, `blur`, `zIndex`, `fixed`, `center`; sem filhos e sem `ariaLabel`
  é puramente decorativo.

### NumberFormatter e PasswordStrength

```tsx
<NumberFormatter value={1234.5} locale="pt-BR" options={{ style: 'currency', currency: 'BRL' }} />

<PasswordStrength value={password} minLength={10} onStrengthChange={setScore} />
```

- `formatNumber(value, locale?, options?)` é exportado como helper. Valores inválidos retornam
  `''`; o componente usa `fallback` (padrão `—`) e aceita `prefix`/`suffix`/`as`.
- `getPasswordStrength(value, minLength?, labels?)` retorna `{ score, label, percentage }` com score
  de 0 a 4. O componente expõe `role="meter"` e `aria-valuenow`/`aria-valuetext`.
